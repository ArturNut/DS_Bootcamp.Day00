# Подробное объяснение скриптов проекта

Этот документ описывает, **что делает каждый скрипт** в папках `ex00`–`ex05` и **как задания связаны между собой** в единый конвейер обработки данных.

Формат: Markdown — файл удобно читается прямо на GitHub (рендерится автоматически) и в VS Code (`Ctrl+Shift+V` — предпросмотр).

---

## Общая идея проекта

Мы строим **конвейер обработки данных (pipeline)** из простых shell-скриптов. Каждый следующий скрипт использует результат работы предыдущего:

```
HeadHunter API
      │  ex00: hh.sh                (скачиваем JSON)
      ▼
 hh.json ──► ex01: json_to_csv.sh   (JSON → CSV)
                 ▼
              hh.csv ──► ex02: sorter.sh        (сортировка по дате)
                             ▼
                        hh_sorted.csv ──► ex03: cleaner.sh   (нормализация названий вакансий)
                                             ▼
                                        hh_positions.csv ──┬──► ex04: counter.sh    (подсчёт уникальных значений)
                                                           │        ▼
                                                           │   hh_uniq_positions.csv
                                                           └──► ex05: partitioner.sh (разбивка по датам)
                                                                        ▼
                                                                  hh_<дата>.csv ──► concatenator.sh (сборка обратно)
                                                                                         ▼
                                                                                    hh_concatenated.csv
```

Контрольная точка: файл `hh_concatenated.csv` из ex05 должен **побайтово совпадать** с `hh_positions.csv` из ex03 — это доказывает, что разбивка и склейка не потеряли ни одной строки.

## Глава ex00 — Первый shell-скрипт

**Файлы:** `hh.sh`, `hh.json` (результат работы)

### Что делает скрипт `hh.sh`

Скрипт скачивает информацию о **первых 20 вакансиях** по запросу из публичного API HeadHunter (по умолчанию — «data scientist») и сохраняет ответ в файл `hh.json`.

### Как это работает по шагам

1. **Определяем поисковый запрос.**
   ```sh
   QUERY="${1:-data scientist}"
   ```
   Берём первый аргумент командной строки (`$1`). Если пользователь ничего не передал, используется значение по умолчанию — `data scientist`. Конструкция `${1:-значение}` означает «взять `$1`, а если он пустой — взять значение после `-`».

2. **Находим папку скрипта.**
   ```sh
   OUTDIR="$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)"
   ```
   `$0` — путь к самому скрипту; `dirname` выделяет из него папку. Благодаря этому файл `hh.json` всегда сохраняется рядом со скриптом, откуда бы мы его ни запустили.

3. **Кодируем пробелы в запросе.**
   ```sh
   ENCODED_QUERY=$(printf '%s' "$QUERY" | sed 's/ /+/g')
   ```
   В URL пробелы нельзя передавать «как есть», их заменяют на `+`. Поэтому `data scientist` превращается в `data+scientist`.

4. **Скачиваем данные через `curl`.**
   ```sh
   curl -s -A "Mozilla/5.0" -H "Accept: application/json" \
       "https://api.hh.ru/vacancies?text=${ENCODED_QUERY}&per_page=20" | jq '.' > "$HHJSON"
   ```
   - `-s` — silent: не показывать прогресс-бар;
   - `-A "Mozilla/5.0"` — представляемся браузером (API HH отклоняет запросы без User-Agent);
   - `-H "Accept: application/json"` — просим сервер ответить в формате JSON;
   - `text=...` — поисковый запрос, `per_page=20` — сколько вакансий вернуть.

5. **Форматируем JSON через `jq`.**
   Конвейер `| jq '.'` берёт «сырой» однострочный JSON от curl и красиво его печатает: каждое поле на своей строке, с отступами. Результат перенаправляется `>` в `hh.json`.

### Что внутри hh.json

Это объект с полем `vacancies` — массивом из 20 вакансий. У каждой вакансии есть `id`, дата публикации `created_at`, название `name`, флаг тестового задания `has_test`, ссылка `alternate_url` и многое другое. Именно эти пять полей мы возьмём в следующем задании.

## Глава ex01 — Преобразование JSON в CSV

**Файлы:** `json_to_csv.sh`, `filter.jq`, `hh.csv` (результат работы)

### Что делает скрипт `json_to_csv.sh`

Извлекает из `hh.json` (результат ex00) список вакансий и превращает его в таблицу **CSV** с пятью колонками:

```
"id","created_at","name","has_test","alternate_url"
```

Результат сохраняется в `hh.csv`. Первая строка — заголовок таблицы.

### Как это работает по шагам

1. **Сам скрипт очень короткий:**
   ```sh
   jq -r -f "$BASEDIR/filter.jq" "$BASEDIR/../ex00/hh.json" > "$BASEDIR/hh.csv"
   ```
   - `-r` — «raw output»: печатать строки без лишних кавычек вокруг строк вывода;
   - `-f filter.jq` — применять правила обработки из файла `filter.jq`, а не из командной строки (так код чище и его можно редактировать отдельно);
   - входной файл — `../ex00/hh.json`, то есть результат предыдущего задания;
   - `>` — весь вывод записываем в `hh.csv`.

2. **Логика фильтра `filter.jq`:**
   ```jq
   (["id","created_at","name","has_test","alternate_url"],
    (.vacancies[] | [.id, .created_at, .name, .has_test, .alternate_url]))
   | map(if . == null then "" else . end)
   | @csv
   ```
   Разберём по частям:
   - Первая строка — массив-заголовок. Он попадёт в CSV первой строкой.
   - `.vacancies[]` — «раскрываем» массив вакансий: каждая вакансия обрабатывается отдельно.
   - `[.id, .created_at, ...]` — из каждой вакансии берём только 5 нужных полей и собираем их в массив-строку таблицы. Оператор `|` (pipe) передаёт результат дальше — как `|` в bash.
   - `map(if . == null then "" else . end)` — если какое-то поле отсутствует (в JSON это `null`), заменяем его на пустую строку, чтобы в CSV не было слова `null`.
   - `@csv` — встроенная функция jq: превращает массив строк в корректную CSV-строку (сама расставляет кавычки и экранирует запятые внутри значений).

### Итог

`hh.csv` — плоская таблица: заголовок + 20 строк вакансий. Это переход от «древовидного» формата JSON к «табличному» CSV, с которым дальше проще работать обычными утилитами.

## Глава ex02 — Сортировка файла

**Файлы:** `sorter.sh`, `hh_sorted.csv` (результат работы)

### Что делает скрипт `sorter.sh`

Сортирует `hh.csv` (из ex01) по возрастанию сначала по колонке **`created_at`** (дата публикации вакансии), а при совпадении дат — по колонке **`id`**. Заголовок таблицы остаётся на первой строке и в сортировке не участвует. Результат — `hh_sorted.csv`.

### Как это работает по шагам

Всего две команды, но в этом вся суть:

1. **Отделяем заголовок от данных:**
   ```sh
   head -n 1 "$SRC" > "$DST"
   ```
   `head -n 1` берёт **первую строку** файла (заголовок) и записывает её (`>`, перезаписывая) в файл результата. Так заголовок гарантированно окажется сверху.

2. **Сортируем только данные:**
   ```sh
   tail -n +2 "$SRC" | sort -t',' -k2,2 -k1,1 >> "$DST"
   ```
   - `tail -n +2` — наоборот, берёт всё, кроме первой строки: начиная со второй строки и до конца;
   - `sort` — стандартная утилита сортировки текстовых строк:
     - `-t','` — разделитель полей — запятая (как в CSV);
     - `-k2,2` — ключ сортировки №1: поле номер 2 (это `created_at`), диапазон `2,2` означает «ровно второе поле»;
     - `-k1,1` — ключ сортировки №2 (запасной): поле номер 1 (`id`) — применяется, когда даты равны;
   - `>>` — **дописываем** отсортированные строки в конец файла результата (не `>`, иначе затёрли бы заголовок).

### Почему именно так

Даты в формате `2020-04-11T18:03:53+0300` устроены так, что обычная **лексикографическая** сортировка (как в словаре) совпадает с хронологической: год стоит первым, затем месяц, затем день. Поэтому `sort` без дополнительных флагов корректно сортирует по времени.

## Глава ex03 — Замена строк в файле

**Файлы:** `cleaner.sh`, `hh_positions.csv` (результат работы)

### Что делает скрипт `cleaner.sh`

Берёт `hh_sorted.csv` (из ex02) и **заменяет название каждой вакансии** на грейд (уровень специалиста), извлечённый из этого названия:

- если в названии встречается слово `Junior` → оставляем `Junior`;
- `Middle` → `Middle`;
- `Senior` → `Senior`;
- несколько слов одновременно → сохраняем все через `/` (например, `Middle/Senior Data Scientist` → `Middle/Senior`);
- ни одно слово не найдено → прочерк `-`.

Заголовок остаётся первой строкой. Результат — `hh_positions.csv`.

### Как это работает по шагам

Здесь используется `awk` — мощный инструмент для построчной обработки таблиц. Команда разбита на логические блоки:

1. **Заголовок пропускаем:**
   ```awk
   NR==1 { print; next }
   ```
   `NR` — номер текущей строки. Для первой строки просто печатаем её как есть (`print`) и переходим к следующей (`next`), не выполняя остальную логику.

2. **Находим границы поля с названием.** Название вакансии — третья колонка CSV. Но если название содержит запятые, оно заключено в кавычки и может «растекаться» на несколько awk-полей. Поэтому скрипт проверяет: если поле начинается с `"` (`$3 ~ /^"/`), ищем поле, которым кавычка заканчивается, — это и есть настоящий конец колонки `name`.

3. **Собираем название целиком:**
   ```awk
   name = $start
   for (i = start + 1; i <= end; i++) name = name "," $i
   ```
   Склейка частей обратно через запятую.

4. **Ищем грейды в названии:**
   ```awk
   if (name ~ /[Jj]unior/) out = out (out == "" ? "" : "/") "Junior"
   if (name ~ /[Mm]iddle/) out = out (out == "" ? "" : "/") "Middle"
   if (name ~ /[Ss]enior/) out = out (out == "" ? "" : "/") "Senior"
   ```
   Оператор `~` — проверка, что строка соответствует регулярному выражению. `[Jj]` допускает любую первую букву (регистронезависимость для начала слова). Хитрость: скобка `(out == "" ? "" : "/")` добавляет `/`-разделитель **только если** в `out` уже что-то есть — так получается `Middle/Senior`, но никогда `/Senior` или `Middle/`.

   ⚠️ Обратите внимание: проверка идёт в порядке Junior → Middle → Senior. Поскольку `Senior` является подстрокой слова… нет, наоборот: `Junior` содержит `unior`, а `Senior` — отдельное слово, поэтому все три проверки независимы.

5. **Если ничего не найдено:**
   ```awk
   if (out == "") out = "-"
   ```

6. **Пересобираем строку:**
   ```awk
   res = $1 "," $2 ",\"" out "\""
   for (i = end + 1; i <= NF; i++) res = res "," $i
   ```
   Берём первые два поля (`id`, `created_at`), затем новое «очищенное» название в кавычках, затем все оставшиеся поля (`has_test`, `alternate_url`). `NF` — количество полей в строке.

### Итог

Вместо длинных «человеческих» названий в колонке `name` теперь короткие категории: `Junior`, `Middle`, `Senior`, `Middle/Senior` или `-`. Данные нормализованы — с ними можно считать статистику (следующее задание).

## Глава ex04 — Описательная статистика

**Файлы:** `counter.sh`, `hh_uniq_positions.csv` (результат работы)

### Что делает скрипт `counter.sh`

Считает, **сколько раз встречается каждое уникальное значение** в колонке `name` файла `hh_positions.csv` (из ex03), и выводит таблицу из двух колонок — `name`, `count` — отсортированную по количеству **по убыванию**. Результат — `hh_uniq_positions.csv`.

Пример содержимого:

```
"name","count"
"-",11
"Middle",5
"Middle/Senior",3
```

### Как это работает по шагам

1. **Пишем заголовок новой таблицы:**
   ```sh
   echo '"name","count"' > "$DST"
   ```

2. **Конвейер обработки данных** (справа налево читать бессмысленно, слева направо — как история):
   ```sh
   tail -n +2 "$SRC" | awk -F',' '{ n = $3; gsub(/^"|"$/, "", n); print n }' | \
       sort | uniq -c | sed 's/^ *\([0-9]*\) \(.*\)/\1\t\2/' | sort -t"$(printf '\t')" -k1,1nr | \
       awk -F'\t' '{ print "\"" $2 "\"," $1 }' >> "$DST"
   ```
   По этапам:
   - `tail -n +2` — отбрасываем заголовок исходного CSV (он нам в подсчёте не нужен);
   - `awk -F','` — берём третье поле (`name`) и функцией `gsub(/^"|"$/, "", n)` срезаем с него обрамляющие кавычки: `^"` — кавычка в начале строки, `"$"` — в конце;
   - `sort` — сортируем значения по алфавиту. **Это обязательно перед `uniq`**, потому что `uniq` склеивает только *соседние* одинаковые строки;
   - `uniq -c` — убирает дубликаты, добавляя перед каждым значением счётчик повторений: `      5 Middle`;
   - `sed 's/^ *\([0-9]*\) \(.*\)/\1\t\2/'` — меняет местами число и текст, разделяя их табуляцией: `5⇥Middle` (число теперь в первом поле — удобно сортировать);
   - `sort -t"<TAB>" -k1,1nr` — сортировка по первому полю (числу): `-n` — как число, `-r` — обратный порядок (по убыванию);
   - финальный `awk -F'\t'` — упаковываем обратно в CSV: `"текст",число`.

### Итог

Получили готовую descriptive statistics: распределение вакансий по грейдам. Такие таблицы — первый шаг к любому аналитическому отчёту.

## Глава ex05 — Разбиение и склейка файлов

**Файлы:** `partitioner.sh`, `concatenator.sh`, `hh_2020-04-11.csv`, `hh_2020-04-12.csv`, `hh_2020-04-13.csv`, `partitions.txt`, `hh_concatenated.csv` (результаты)

Задание состоит из двух скриптов, работающих в паре.

### Скрипт `partitioner.sh` — разбиение по датам

Берёт `hh_positions.csv` (из ex03) и раскладывает строки по отдельным файлам **в зависимости от даты публикации** (`created_at`). Каждая дата получает свой файл вида `hh_ГГГГ-ММ-ДД.csv`, и в каждом файле — своя копия заголовка таблицы.

По шагам:

1. **Чистим результаты прошлых запусков:**
   ```sh
   rm -f "$BASEDIR"/hh_*.csv "$BASEDIR/partitions.txt"
   ```
   `-f` — не ругаться, если файлов ещё нет. Это делает скрипт **идемпотентным**: сколько раз ни запускай, результат одинаков (старые «осколки» не смешиваются с новыми).

2. **Запоминаем заголовок:**
   ```sh
   HEADER=$(head -n 1 "$SRC")
   ```
   Подстановка `$(...)` выполняет команду и сохраняет её вывод в переменную — заголовок понадобится многократно.

3. **Построчно читаем данные:**
   ```sh
   tail -n +2 "$SRC" | while IFS= read -r line; do
   ```
   Цикл `while read` — классический способ обработать файл построчно. `IFS=` и `-r` — защитные флаги: не обрезать пробелы по краям строки и не интерпретировать обратные слеши.

4. **Вытаскиваем дату из строки:**
   ```sh
   date=$(printf '%s' "$line" | awk -F',' '{ print substr($2, 2, 10) }')
   ```
   Второе поле — например `"2020-04-11T18:03:53+0300"`. `substr($2, 2, 10)` берёт из него 10 символов, начиная со второго (пропускаем открывающую кавычку) → получаем `2020-04-11`.

5. **Создаём файл-партицию при первой встрече даты:**
   ```sh
   if [ ! -f "$part" ]; then
       printf '%s\n' "$HEADER" > "$part"
       printf '%s\n' "${part##*/}" >> "$LIST"
   fi
   ```
   Файл `hh_<дата>.csv` ещё не существует → создаём его с заголовка (`>`). Имя нового файла добавляем в список `partitions.txt` (`${part##*/}` — отсечение пути, остаётся только имя).

6. **Дописываем строку в нужный файл:**
   ```sh
   printf '%s\n' "$line" >> "$part"
   ```
   `>>` — дописывает в конец, ничего не перезаписывая. Строки внутри каждой партии сохраняют исходный (отсортированный) порядок.

### Скрипт `concatenator.sh` — сборка обратно

Берёт все файлы-партии и **склеивает их в один CSV** — `hh_concatenated.csv`. Заголовок при этом оставляется ровно один раз, в первой строке. Правильный результат обязан побайтово совпасть с `hh_positions.csv` из ex03.

По шагам:

1. **Собираем список партий по алфавиту:**
   ```sh
   PARTS=$(ls "$BASEDIR"/hh_[0-9]*.csv 2>/dev/null | sort)
   ```
   Маска `hh_[0-9]*.csv` ловит только файлы с датой в имени (`hh_2020-04-11.csv`), но не, например, сам `hh_concatenated.csv` (после буквы `hh_` идёт `c`, не цифра). `2>/dev/null` глушит ошибку `ls`, если файлов пока нет. `sort` важен: имена дат в ISO-формате при алфавитной сортировке автоматически выстраиваются хронологически, восстанавливая исходный порядок строк.

2. **Флаг «заголовок уже записан»:**
   ```sh
   header_done=0
   ```
   Простая переменная-переключатель: `0` — заголовок ещё не писали, `1` — уже писали.

3. **Цикл по партиям:**
   ```sh
   for part in $PARTS; do
       if [ "$header_done" -eq 0 ]; then
           head -n 1 "$part" >> "$DST"
           header_done=1
       fi
       tail -n +2 "$part" >> "$DST"
   done
   ```
   Для первой партии дополнительно пишем её заголовок (`head -n 1`) и ставим флаг. Для **каждой** партии берём только данные (`tail -n +2`) — так заголовки остальных файлов отбрасываются и в итоговом файле оказывается ровно одна строка заголовка.

### Итог

Разбили большой файл на «удобные куски» по дате, а затем собрали обратно без потерь. Этот приём — основа работы с большими данными: партиционирование ускоряет чтение (аналитик открывает только нужный день) и позволяет параллельно обрабатывать части.

### Используемые утилиты (и зачем они здесь)

- **`curl`** — делать HTTP-запросы из командной строки;
- **`jq`** — «sed для JSON»: фильтровать, преобразовывать и форматировать JSON;
- **`head` / `tail`** — брать начало / конец файла (классический способ отделить заголовок CSV);
- **`sort`** — сортировка строк с указанием разделителя и ключей;
- **`uniq -c`** — подсчёт повторов (всегда после `sort`!);
- **`cut`-подобная логика в `awk -F','`** — выбор колонки из таблицы;
- **`grep` / регулярные выражения** — поиск шаблонов (`[Jj]unior`);
- **`sed`** — замена текста по шаблону.
